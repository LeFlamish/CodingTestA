- 전역 변수를 지향하자. 어디서든 접근이 가능하고, 자동으로 0으로 초기화가 된다.
- 무슨 일이 있어도 문제는 반드시 제대로 읽고 이해를 한 다음에 풀기 시작하자.
- 세로축은 행(R)이고, 가로축은 열(C)이다.
- 2차원 배열의 크기가 주어질 때 N, M 순으로 주어지면 90% 이상은 먼저 나오는 숫자가 세로축 값이다.
- 2차원 배열 범위 함수는 반드시 따로 만들자(ex. OOB, isArea 등).
- 반드시 동작마다 함수를 만들자. 동작의 순서 또한 매우 중요하다.
- 동작과 조건을 구분할 수 있어야 한다.
- 2~3줄만에 끝나는 함수는 함수 선언 시, 자료형 앞에 inline을 붙여주자. 다만 요즘은 컴파일러 성능이 좋아서 inline 안붙여도 자동으로 컴파일러가 붙여주지만 본인은 붙이는 습관이 있다.
- 자주 나오는 유형(중력 작용, 배열 회전 등)은 반드시 암기하자.
- 최단거리, 무리(덩어리) 만들기는 반드시 BFS이다.
- 무리짓기에서 BFS의 실행 횟수가 곧 무리의 개수이다.
- 공부를 하면서 void 형태의 함수를 많이 만들게 되고 습관이 되어버리는데, 좋지 않다. 함수의 반환형은 언제나 다양하게 내 마음대로 할 수 있음을 명심하자.
- 반드시 하나의 객체로 판단할 수 있는 것들은 구조체로 만들 생각을 하자. (ex. 사람, 벌레, 로봇, 불, 장애물 등). 객체가 가진 특성, 특징을 담는다.
- 구조체를 만들 때, 우선 순위가 있는 문제들은 operator < 함수를 만들자.
- 알고리즘은 생각보다 많은 것들을 자동으로 처리해준다. 하지만 시작점, 끝점 등은 판단할 수 없다. 따라서 시작점과 끝점 등 일부분에 있어서는 무식하게 다 돌아보는 브루트포스를 기본적으로 생각해야한다.
- int값 자체로 True, False가 된다. 0은 False이고, 0을 제외한 나머지 모든 정수는 True이다. 적극적으로 활용하자.
- bit 연산자 &로 홀짝 판별이 훨씬 빠르고 쉽게 가능하다. (a & 1)이 True면 홀수, False면 짝수다.
- 예제 설명을 그대로 비교할 수 있도록 2차원 배열과 상태를 출력하는 Debug() 함수를 만들어서 그대로 따라가며 비교해보자.
- Visual Studio에서는 맞는데 코드트리에서는 틀리다면, 그냥 틀린 코드다. Visual Studio는 Segmentation fault(배열 크기를 넘어선 인덱스 접근 등)와 같은 오류들을 컴파일러가 잡아줘서 통과되는 것이다. 다시 풀자.
- 코딩테스트는 실생활 문제 풀이이다. 우리가 상상할 수 있는 실제 세계에서 돌아가는 시뮬레이션 문제라는 뜻이다. 그렇기 때문에 실제로 세상이 돌아가는 것처럼 시뮬레이션 그대로 풀어라.
  예를 들어, 불이 번지고 사람이 탈출해야하는 경우에 불을 모두 다 먼저 이동시키고 사람을 이동시키면 절대 안 된다. 그게 편할 것 같지만, 정답률은 현저히 낮아진다. 반드시 실제 세계처럼 1초, 1초, 1턴, 1턴 실행되도록 풀자.
- 2차원 배열 board가 꼭 int형일 필요는 없다. 모든 칸에 객체가 있다면, 구조체 자료형으로 2차원 배열을 선언하는 것이 좋을 때가 있다.
  예를 들어, 2차원 배열 위에 여러 가지 정보를 동시에 표시하고 싶다거나 모든 칸에 있는 각각의 객체가 격자 위에서 이동이 없을 때 사용 가능하다.
